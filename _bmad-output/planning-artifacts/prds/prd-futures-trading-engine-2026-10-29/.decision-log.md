# Decision Log — Futures Trading Engine

Series continues in this file. Each accepted decision takes the next free `D<n>`.
Status values: `proposed` (default in the PRD, not yet confirmed by Martin) · `accepted` · `rejected` · `superseded`.

| # | Date | Decision | Rationale | Status |
|---|---|---|---|---|
| D1 | 2026-10-29 | The engine is a **config-driven single-strategy runner**, not a lifecycle platform (no promotion state machine, no registry UI, no multi-account). | John: the value is "one description, two modes". Everything else is gold-plating with no second consumer. | proposed |
| D2 | 2026-10-29 | `prd-ibkr-futures-2026-06-15` is **superseded** as the authority for futures execution; its broker lessons are absorbed, its MES-only and desktop-UI scope are dropped. | It was marked "finalized" in June 2026 and the live half was never delivered. A document status is not evidence of execution (Mary A7). | proposed |
| D3 | 2026-10-29 | The existing **75 `Run*.java` coexist** with the config engine; each is deleted only once its config equivalent passes the F2 parity test. | Deleting them in one pass destroys the only record of how each was configured. | proposed |
| D4 | 2026-10-29 | Strategies keep the existing **`Strategy` contract returning `Order`** (which already carries `stopLoss`, `takeProfit`, `ocaGroup`, `parentId`). No new `Signal` type. | Introducing `Signal` would rewrite 32 strategies for no capability gain (Winston's intent is preserved: `Order` is a value object, only the broker executes). | proposed |
| D5 | 2026-10-29 | **IBKR stop support ships first**, inside this PRD, not as a follow-up epic. | `IbkrBroker.submitOrder` silently drops `stopLoss`/`takeProfit` (`IbkrBroker.java:134`), so every live entry is a naked position today. | proposed |
| D6 | 2026-10-29 | Runs are declared in **`config/runs/<strategy>-<symbol>-<mode>.json`**, validated at startup. | JSON is already the project's config language; an unknown strategy, symbol or mode must refuse to start. | proposed |
| D7 | 2026-10-29 | **One container per run config**, as today. | Preserves the deployed lane's isolation, the reconciler's assumptions, and the guard against two runners on one instrument. | proposed |
| D8 | 2026-10-29 | A strategy may run live only if its config **names the backtest that validated it**, or sets `unvalidated: true` (paper only). | Makes "the thing I tested is the thing that trades" enforceable instead of aspirational (F5). | proposed |
