# Story 46.2: CME Native OCA Bracket Order Router & Hybrid Stop-Loss Engine

Status: ready-for-dev

## Story

As a quantitative trader,
I want entry orders to automatically submit exchange-native CME OCA (One-Cancels-All) bracket orders (hard Stop-Market + Take-Profit targets) directly through Interactive Brokers, with the Java daemon adjusting trailing stops dynamically at bar closes,
So that my capital is protected directly on CME exchange matching engines against flash crashes and internet disconnects, while still allowing intelligent software-driven trailing stops.

## Acceptance Criteria

1. **Given** a trade entry signal generated by a swing strategy:
   - `IbkrBracketOrderRouter.java` constructs a parent entry order (`MKT` or `LMT`) and two child orders: a Stop-Loss (`STP`) and Profit Target (`LMT`).
   - The child orders are grouped under a unique `ocaGroup` ID with `ocaType = 1` (Cancel all remaining orders with block).
2. **When** the entry order is submitted and filled by the CME exchange:
   - Both the Stop-Loss and Profit Target orders are automatically activated directly on the broker/exchange servers.
   - If price reaches the Stop-Loss price, CME executes a Stop-Market order and cancels the Profit Target instantly on the exchange.
3. **When** an H1 or D1 bar closes and the strategy calculates an updated trailing stop or breakeven level:
   - The Java engine issues an `orderModify` request to update the active Stop-Loss price with the quantized tick price.
   - If the modification is rejected or the connection is down, the original exchange disaster stop remains intact.
4. **And** unit and integration test `IbkrBracketOrderRouterTest.java` passes with 100% verification of bracket creation, OCA group assignment, and trailing stop modifications.
